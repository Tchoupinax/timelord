That means a lot for me. I will explain to you why.

I enjoy to test technologies, to find projects I might be interested in and to deploy in my cluster. All technologies and softwares I use in my cluster are open source and free. I love the open source philosophy and what it means in this world: we are all sharing our work and our knowledges. We are all colleagues in the same ship and we go to the same destination. It really matters. In this world where anything must be valuable, we might take time to think about how much we take from the open source community and how we could not make it without its work.

Open source means really more than just "a geek made another library". It is a vision of share. It is better for efficiently, independency and security. Each can use the work made by others and contribute with the things he does best. Some can do many things, some cannot.

It's not fair.

## History of the project

![d](https://d3d0lqu00lnqvz.cloudfront.net/media/new_article_images/Gender/IISC_EqualityEquity.png)

I used to create many projects for fun and for my own usage. I try to contribute as much as I can by summitting issues and pull requests to project I am using. I also publish softwares that might be usable by others people.

But, often, it asks many to finalize and publish a whole project to the community, having done the work of abstraction to make the project usable by everyone. It is where I am often blocked. It is easy to build something that matches your personal need, that's why I tend to create the tools myself as soon as I do not find something really relevant, it is harder to make it ready for everyone.

I started this project like two years ago. I managed many backups scripts and CRON jobs. For a while, those scripts were performed by my Continuous integration, [Woodpecker CI](https://woodpecker-ci.org/). The issue is, it might fail and CI is really not the thing you want to make backups of your precious data. I had a lot of probleme because my CI was not healthy.

I used CRON job directly with Linux to make those backups but I have to tell it's quite painful to maintain and manage. I did not remember which server is doing what. I did not know if the script has failed this night. I have to connect the server with administrator rights, I have to edit a script with Terminal shell and I have to check CRON execution. Honestly, it was not good.

I gave a look about what is made in the community about backups. They are very good and known softwares like [rclone](https://rclone.org/), [restic](https://restic.net/). A new community was attracted around [Plakar](https://plakar.io/). Honestly I found many things but it does not fit exactly what I wanted. I loved what I was doing, the issue is about the way scripts were transfered to machines and monitored. It would be so cool if those scripts are in a **centralized** git repository, managed **as code** like every pieces of my infrastructure and executions are just in **stateless agents**.

:::info
Timelord is a centralized way to manage your reccurent jobs and backups as code, performed by lightweight agents.
:::


That is what defining Timelord. I created a web interface that manages resources with a classic HTTP API and Postgres database. This server can connect to my personnal [gitea](https://about.gitea.com/) instance to fetch my scripts. Each script describes actions to take, when it must be done and which agent needs to take it. I can create and host an agent everywhere I want so it means I can start a script in the specific context I need (In the server A? Inside production cluster without exposing it?). The pull model is really insteresting because you do not need to manage network flux, only the server must be reacheable.

## Preview

Like the **Custom Resource Definition** model in Kubernetes, the script brings all data by itself.

```bash
#!/bin/bash

#>> Timelord
#>> What: Example timelord     <<= Title of the script
#>> When: 0 */1 * * *          <<= CRON expression
#>> KeepLast: 10               <<= Memory last 10 executions (logs)

# --- Inside this line, do whatever you want. It's Bash.

# Very important to throw error!
set -e

echo "Hey it's a test of timelord!"

echo "This script will be performed on machine A"
```

What I really like is that you are not limit inside the job. The job represents execution of a bash script, but this script can be alone or accompanied with assets, like terraform files, zip, etc... So you can provide your terraform files and Timelord will be in charge to send those files to the correct agent when it needs to be performed and ensures that it will be executed. In the dashboard, you will see if the execution is a success or not, with output logs.
